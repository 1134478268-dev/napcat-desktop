# NapCat Desktop 用户手册

## 这是什么

NapCat Desktop 是一个基于 NapCat 的 Windows 原生桌面管理面板。它不是网页，而是一个双击就能跑的 EXE，用来帮你启动、监控和配置 NapCat QQ 机器人协议端。

它是一个**纯本地程序**：不联网、不上传任何数据、不需要注册账号。所有配置都保存在你自己的电脑上（位置见下方「程序在哪里、数据在哪里」）。

---

## 系统要求

- 操作系统：Windows 10 或 Windows 11（64 位）
- 运行环境：WebView2 Runtime（Windows 10/11 现已自带，一般无需单独安装）
- 前置条件：你已经安装好了 NapCat（官方 `NapCat.Shell` 解压包，或带 `bootmain` 的整合包）

---

## 程序在哪里、数据在哪里

| 内容 | 位置 |
| --- | --- |
| 程序本体 | 你放在哪就在哪，免安装、可拷贝。NSIS 安装版默认在 `Program Files` |
| 面板配置 | `%APPDATA%\com.napcat.desktop\napcat-desktop.json` |
| 错误日志 | `%APPDATA%\com.napcat.desktop\logs\error.log`（**只**记录 WARN / ERROR，方便排查） |
| 手动导出的日志 | `%APPDATA%\com.napcat.desktop\logs-<时间戳>.txt` |

删掉 `napcat-desktop.json` 即可恢复出厂设置（**不会**动到你的 NapCat 数据和 QQ 登录态）。

## 首次启动

1. 双击 `NapCatDesktop.exe` 启动程序。
2. 首次启动会自动扫描常见的 NapCat 安装路径，包括：
   - `D:\`、`C:\` 根目录下含 `napcat` 关键字的文件夹
   - `%ProgramFiles%\napcat`、`%ProgramFiles(x86)%\napcat`
   - `%LOCALAPPDATA%\Programs\napcat`、`%APPDATA%\napcat`
   - `D:\Apps\NapCat.Shell`、`D:\napcat` 等常见安装位
3. 自动检测命中后，路径会自动填进设置里，你可以直接开始使用。
4. 检测不到就点设置页的「**浏览**」手动选择目录——请选中**包含启动脚本的那一层**
   （官方包是 `launcher.bat` / `launcher-user.bat` 所在目录；整合包是 `shell\`、`bootmain\` 的上一层）。

> 出于安全考虑，自动检测**不会**扫描桌面和「下载」文件夹——否则有人往那里丢一个伪造的 `launcher.bat`，就可能被误执行。所以这两个位置需要你手动选择。

## 账号管理

### 添加 / 删除 QQ 号

1. 打开「账号」页，点「添加 QQ 账号」。
2. 输入 5–11 位纯数字 QQ 号（不是纯数字会被拒绝）。
3. 卡片右下角「删除」只从**桌面端配置**里移除，**不会**删除 NapCat 目录下的 `config/napcat_<QQ>.json`，也不会注销登录态。

### 「启用」开关是干什么的

每张卡片上都有一个启用开关：

- **启用**：点概览页的「启动 NapCat」且没有指定 QQ 号时，程序会挑**第一个被启用的账号**去登录。
- **禁用**：启动时跳过这个号。

禁用**不会**停止正在运行的账号，也不会删除任何配置，它只影响「不指定 QQ 号启动时选谁」。

### 卡片的启动 / 停止按钮

- 点「启动」= 用**这个** QQ 号拉起 NapCat。
- 点「停止」= 停止 NapCat 主进程（注意：NapCat 一次只跑一个账号，所以停止是针对整个进程的）。

### 备注有什么用

备注只是本地显示用的标签，方便你在多个号之间区分，**不影响登录流程，也不会上传到任何地方**。鼠标悬停昵称会出现铅笔图标，点它即可就地编辑。

### 登录态怎么保存

QQ NT 协议第一次需要扫码登录。扫码成功后，**登录态由 NapCat 自己保存在它的工作目录下**（不是保存在桌面端）。

之后启动时程序会用 `-q QQ号` 参数拉起 NapCat，自动恢复之前的登录态，不需要每次都扫码。

桌面端**只记录"这个账号是否成功登录过"**这一件事（卡片上显示「已记住登录态」/「需扫码登录」），它**不保存、也不加密任何 token**。

### 扫码登录

如果 NapCat 需要扫码，程序会识别它的日志，**自动弹出二维码窗口**，用手机 QQ 扫码即可。登录成功后窗口会自动关闭。

## 启动 / 停止 NapCat

### 「启动」按钮做什么

点击后，程序会按照你选好的路径拉起 NapCat 子进程，并接管它的标准输出 / 错误输出，显示在日志页里。

程序支持两种安装形态，会自动判断：

1. **整合包形态**：目录下有 `shell\node.exe` 和 `shell\index.js` 时，直接启动 `node.exe`（同时读取目录下的 `quick-login.env` 注入登录参数）。这是最稳的方式，也避开了 `.bat` 在中文系统下的编码问题。
2. **脚本形态**：按以下顺序找启动器——`launcher-user.bat` → `launcher.bat` → `start-napcat.bat` → `napcat.exe` → `start-napcat.ps1` → `shell\napcat.bat`。

两种形态都在后台运行，**不会弹出黑色命令行窗口**。

### 「停止」按钮做什么

点击后，会向 NapCat 进程树发送强制结束（含子进程），并在后台确认进程真的退出了。停止时也会同时关掉"自动重启"，避免刚停就被拉起来。

### 概览页状态徽章

| 徽章 | 含义 |
| --- | --- |
| 未运行 / 已停止 | NapCat 没有在跑 |
| 运行中 | NapCat 正在运行 |
| 进程已崩溃 | 异常退出且已放弃自动恢复，需要手动处理 |
| 重启次数: n | 本次会话内已经被自动拉起过几次 |

## 崩溃自动恢复

### 自动重启规则

当 NapCat 进程以**非零退出码**结束时，程序会自动尝试重启：

```
第 1 次失败 → 等 1 秒  后重启
第 2 次失败 → 等 2 秒  后重启
第 3 次失败 → 等 4 秒  后重启
第 4 次失败 → 等 8 秒  后重启
第 5 次失败 → 等 16 秒 后重启
```

也就是指数退避，最多自动重启 5 次（可在设置页改成 3 / 5 / 10 次）。

**例外**：整合包（`node.exe`）形态下**不会**自动重启。因为在这种形态下 node 退出基本都是业务错误（重复登录、配置错误、你自己关了 QQ），自动重启只会反复报同一个错。

### 5 次都失败会怎样

程序会放弃自动重启，状态徽章变成「进程已崩溃」。这时候通常是 QQ 登录态失效或者 NapCat 本身配置有问题，需要你手动排查后再点「启动」。

### 「模拟崩溃」按钮是干嘛的

这是一个测试按钮。点下去会**真的把当前 NapCat 子进程杀掉**，用来验证自动恢复逻辑是否正常工作。日常使用不需要点它。

## 插件管理

### 插件目录

- 整合包结构：`<NapCat 目录>\shell\plugins\`
- 官方结构：`<NapCat 目录>\plugins\`

程序会自动识别用的是哪一种（设置页会显示当前实际使用的插件目录）。

### 刷新插件列表

进入「插件」页，点右上角「刷新」，程序会重新扫描插件目录并读取每个插件的 `package.json`（名称 / 版本 / 描述 / 作者）。

### 启用 / 禁用怎么操作

**请用 NapCat 自带的 WebUI（插件市场）来启用 / 停用插件**，那是官方的方式，改完对 NapCat 立即生效。

本面板**不提供**插件开关，只做**只读展示**：它在列表里读取的是"插件目录名是否带 `.disabled` 后缀"。

- 目录名是 `anti-recall` → 面板显示「已启用」
- 目录名是 `anti-recall.disabled` → 面板显示「已禁用」

> ⚠️ 注意：`.disabled` 后缀是**本面板自己的识别规则**，不是 NapCat 的官方约定。
> 也就是说，你手动给目录改名后，NapCat 未必会因此停止加载该插件。
> 需要真正启停插件时，请以 NapCat WebUI 里的操作结果为准。

### 拖拽安装插件（推荐）

把**插件文件夹**或 **`.zip` 压缩包**直接拖到插件页底部的虚线框里，程序会自动复制 / 解压到插件目录。同名插件已存在时会拒绝覆盖，不会悄悄替换你已有的文件。

### 从「可选插件」一键安装

插件页分成三个区域：

| 区域 | 内容 |
| --- | --- |
| **默认插件** | 目录名能在本面板推荐清单里找到的插件（也就是从下面「可选插件」装进来的） |
| **自定义插件** | 你自己放进插件目录的插件 |
| **可选插件** | 精选自 NapCat 官方插件索引与 GitHub 社区的推荐列表（约 10 个） |

在「可选插件」里点：

- **「安装」** —— 自动下载该插件的发布包并解压到插件目录（装完会自动刷新，插件随即出现在「默认插件」区）。带「安装」按钮的都是官方索引里提供了现成发布包的插件。
- **「仓库」** —— 在浏览器打开该插件在 GitHub 的仓库，自己看说明。
- **「需自建」** —— 该仓库没有提供可直接安装的包（只有源码），需要你按仓库说明自行构建后再拖进来。面板不会假装能一键装。

> **关于下载网络**：本面板会先直连 GitHub；如果直连失败（国内常见），会自动改用公共镜像
> （`ghproxy.net` / `gh-proxy.com` / `ghfast.top`）重试。都不通时，可以在「设置 → 代理」里
> 填入你的代理再试，或先在浏览器下载 zip 再拖进插件目录。
> 每次安装的结果（含失败原因）都会记到 `%APPDATA%\com.napcat.desktop\logs\error.log`，前缀是 `[plugin-install]`。

### 插件备注

每张插件卡片底部可以写备注（点「添加备注…」）。备注**保存在面板配置里**，按插件目录名索引，方便你记住每个插件是干嘛的。

### 启动机器人（NoneBot2）

如果你的插件目录里放的是一个 NoneBot2 项目（即某个子目录下有 `bot.py`），可以用插件页右上角的「**启动机器人**」按钮把它跑起来。

- 程序会找到第一个 `bot.py`，在它所在目录执行 `python bot.py`，日志以 `[bot]` 前缀混在日志页里。
- 机器人进程**不会**自动重启。它退出时会在日志里提示，并弹一个警告 toast。
- 需要停止就再点一次同一个按钮（会变成「停止机器人」）。

## OneBot 网络配置

在「网络」页可以配置 OneBot 协议对外暴露的接口：

| 类型 | 用途 |
| --- | --- |
| **HTTP** | 监听地址和端口，供上游主动请求 |
| **WS（正向）** | 监听地址和端口，供上游主动连进来 |
| **反向 WS** | 填对方机器人框架的地址，由 NapCat 主动连过去（**必须填地址**） |

每个服务还可以填：

- **端口**：1–65535，填错会被拦下
- **Token**：可选的鉴权 token（列表里只显示前 4 位）
- **备注**：给自己看的说明

「编辑」就地展开表单，「删除」二次确认后移除。改动会写进面板配置并整体保存。

> 这些配置最终要写进 NapCat 自己的配置文件才生效。面板负责收集与持久化你的意图，具体热重载行为以 NapCat 版本为准。

## 日志视图

「日志」页实时显示 NapCat 的 stdout / stderr。

### 颜色含义

| 颜色 | 含义 |
| --- | --- |
| 红色 | ERROR，出错了，需要关注 |
| 黄色 | WARN，警告，不一定是错但要留意 |
| 蓝色高亮 | RECV，表示收到了一条来自 QQ 的消息 |
| 紫色 | 插件加载相关日志 |
| 绿色 | OK，正常状态提示 |
| 默认 | 普通信息日志 |

### 工具栏

- **级别下拉**：只看某一类日志
- **关键字过滤**：输入即过滤
- **暂停**：暂停**自动滚动与增量刷新**（日志仍在后台保留，恢复后能看到这期间的日志）
- **清空**：只清空界面上的缓冲区，不动磁盘文件
- **导出**：把当前日志写到 `%APPDATA%\com.napcat.desktop\logs-<时间戳>.txt`，并提示完整路径

### 日志会保存吗

- 界面上最多保留最近 **200 条**，**关闭程序就没了**。
- 只有 **WARN / ERROR** 级别会被自动追加到 `logs\error.log`（方便事后排查）。
- 需要完整日志请在 NapCat 侧开启文件日志。

### token 会被打码吗

会。日志在推送到界面前，`token=` / `access_token=` / `authorization` 后面的内容会被替换成 `***`，避免你截图或录屏时泄露凭据。

## 系统托盘

- 点窗口右上角的 `X`，**不会退出程序**，而是最小化到系统托盘。
- 托盘图标右键菜单有两项：
  - 「显示主窗口」：把面板叫回来
  - 「退出」：真正结束 NapCat Desktop
- **关闭程序不会结束 NapCat 子进程**——NapCat 会继续在后台运行。要一起停掉，请先在概览页点「关闭 NapCat」。

---

## 双主题与自定义窗口

- 右上角太阳 / 月亮图标切换「浅色 / 深色」，切换即时生效，下次启动会记住。
- 窗口是无边框自绘标题栏，用标题栏空白处拖动窗口，右上角三个按钮分别是最小化 / 最大化还原 / 关闭（关闭 = 最小化到托盘）。

## 常见问题 FAQ

### 1. 点「启动」没反应，或者立刻报错退出怎么办

先检查这几点：

1. 到「设置」里确认 NapCat 路径选对了，目录下确实有 `launcher.bat` 或 `shell\node.exe` 之类的启动入口。
2. 右键 `NapCatDesktop.exe`，用「管理员身份运行」试一次（有时候 `launcher.bat` 需要写权限）。
3. 看日志页有没有红色 ERROR，把报错信息复制出来排查。

### 2. 提示「未找到启动脚本」怎么办

说明你选的目录能被识别成 NapCat 目录，但里面没有可用的启动入口。请确认选的是**正确的那一层**：

- 官方包：应该是 `launcher.bat` / `launcher-user.bat` 所在的目录
- 整合包：应该是 `shell\`、`bootmain\` 的**上一层**

### 3. 一直崩溃、自动重启 5 次后停在「进程已崩溃」怎么办

最常见的原因是 **QQ 登录态失效**。解决办法：

1. 手动进到 NapCat 目录，用原来的方式（命令行 / `launcher.bat`）起一次。
2. 扫码重新登录。
3. 登录成功后，再回到 NapCat Desktop 点「启动」。

### 4. 插件列表是空的怎么办

1. 打开「设置」，确认 NapCat 安装路径指向的是**真正的 NapCat 根目录**。
2. 看插件页顶部显示的"插件目录"是否合理（整合包应在 `shell\plugins`）。
3. 目录不存在时程序会自动创建；把插件放进去，回插件页点「刷新」。

### 5. 配置乱了 / 设置错了，想恢复默认怎么办

直接删除：

```
%APPDATA%\com.napcat.desktop\napcat-desktop.json
```

删完重新启动 `NapCatDesktop.exe`，就会走首次启动的扫描流程。注意：这不会动到你的 NapCat 数据和 QQ 登录态，只是重置面板自己的设置。

### 6. 启动时报 WebView2 相关错误怎么办

说明系统里的 WebView2 Runtime 有问题或者缺失。解决办法：

1. 打开系统「设置 → 应用」，看看有没有「Microsoft Edge WebView2 Runtime」。
2. 没有的话，去微软官网下载安装 Evergreen 版 WebView2 Runtime，装完重启电脑。
3. Windows 10/11 较新版本一般都自带，如果是精简版系统需要手动补装。

### 7. 关掉面板后 QQ 机器人还在跑，正常吗

正常。面板是"管理器"，关闭面板不等于关闭 NapCat。想一起停掉，先在概览页点「关闭 NapCat」，再关面板。
